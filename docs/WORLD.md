# 무한 대륙이 만들어지는 방법

이 문서는 `src/world/` 를 고치기 전에 읽는다.
지형은 여러 시스템이 같은 답을 전제로 움직이기 때문에, 한 곳만 고치면
플레이어가 땅에 파묻히거나 소품이 공중에 뜬다. 실제로 그렇게 됐었다.

---

## 1. 규칙 하나: 높이를 아는 곳은 오직 한 군데

```
Terrain.heightAt(x, z)   ← 이것이 유일한 답이다
```

높이를 묻는 곳이 많다.

| 묻는 쪽 | 왜 |
|---|---|
| `Chunk._ground()` | 지형 메시의 정점을 올린다 |
| `Chunk._props()` | 나무·바위를 땅에 세운다 |
| `Player.update()` | 발을 디딜 자리 |
| `Enemy.update()` · `PartyMember.update()` | 걸어 다닐 자리 |
| `Encounters.populateChunk()` | 적을 세울 자리 |

이들이 제각기 계산하면 아주 작은 차이로도 어긋난다.
**새 코드에서 높이가 필요하면 반드시 `terrain.heightAt()` 을 부른다.**
직접 노이즈를 계산하지 않는다.

같은 이유로 물도 하나다 — `Terrain.waterDepth(x, z)`.

---

## 2. 층 구조

대륙은 두 층이다. 경계를 잘못 잡으면 손으로 지은 것이 절차적 지형에 묻힌다.

```
        0m ─────── 225m ─────── 345m ─────────────── 1800m ── 2100m
        │           │            │                      │        │
        │ 완전 평지  │  섞이는 구간 │   절차적 지형          │  바다로 │
        │           │            │                      │  내려감  │
        └ 손으로 지은 세계 ┘        └ 여기부터 진짜 무한 ────────────────
             (건물·길·다리)
```

| 상수 | 값 | 왜 그 값인가 |
|---|---|---|
| `VILLAGE_FLAT` | 225m | **손으로 지은 것이 220m까지 뻗는다.** 그 소품은 전부 y=0에 놓여 있으므로 이 안은 평지여야 한다 |
| `VILLAGE_BLEND` | 120m | 225→345m에서 서서히 지형이 살아난다. 갑자기 솟으면 벽처럼 보인다 |
| `VILLAGE_BUILT` | 240m | 절차적 소품을 놓지 않는 범위. 평지보다 **조금 넓게** — 길이 118m까지 뻗어 있어 딱 맞추면 길 끝에 나무가 자란다 |
| `WATER_LEVEL` | −1.2m | 수면은 하나다. 여기저기 다르면 어디가 물인지 눈으로 못 가늠한다 |
| `SEA_START/FULL` | 1800/2100m | 사실상 무한이지만 끝은 있다 |

> **손으로 지은 것을 추가할 때**는 원점에서 얼마나 먼지 재고,
> 220m를 넘으면 `VILLAGE_FLAT` 을 함께 늘린다.
> `node tools/check-terrain.mjs` 가 그 범위의 평지 여부를 확인한다.

## 3. 청크

`Chunk` 하나는 64m 정사각형이고, 자기 것을 **전부** 들고 있다.

```
Chunk
 ├── 지형 메시   (24×24 격자 = 2.7m 간격, 정점 색은 그 자리의 바이옴에서)
 ├── 물 표면     (지형이 수면보다 파인 청크에만)
 ├── 소품 메시   (불투명 1개 + 반투명 1개 — 색을 정점에 구워 재질을 합친다)
 └── 충돌 상자   (collision에 chunk.key 를 소유자로 달아 둔다)
```

이 자족성이 중요하다. 청크가 서로 얽히면 하나를 버릴 때 다른 청크가 깨진다.
`dispose()` 가 씬·충돌·지오메트리를 한 번에 걷어낸다.

### 왜 청크당 드로우콜이 3개인가

소품 종류마다 재질을 두면 청크 하나가 8~9개를 먹고, 25청크면 200개가 넘는다.
그래서 **색을 재질이 아니라 정점에 굽는다**(`mergeColored`). 나무든 바위든
버섯이든 재질이 하나라 한 번에 그려진다. 반투명한 것(소금·수정·물)만 따로 묶는다.

대가로 소품에서 텍스처가 빠지지만, 원래 셀 셰이딩이라 면이 단색으로 떨어지고
손으로 지은 마을은 텍스처를 그대로 쓴다.

### 경계가 네모나지 않게

청크 중심의 바이옴 하나로 색과 소품을 정하면 64m 네모가 격자로 드러난다.
그래서 둘 다 **자기 자리의 바이옴**을 따른다.

- 색: 정점마다 `terrain.biomeAt(정점 좌표)`. 삼각형 안쪽은 GPU가 보간한다
- 소품: 이웃 바이옴 것까지 후보로 두고, 놓을 때 그 자리의 바이옴이
  그 소품을 갖고 있는지 확인한다

## 4. 스트리밍

`ChunkManager` 가 플레이어를 따라 만들고 버린다.

| 장치 | 값 | 왜 |
|---|---|---|
| 시야 반경 | 3 (192m), 저사양 2 | 안개가 175m에서 닫히므로 경계가 안 보인다 |
| 버리는 반경 | 시야 + 1.5 | 같으면 경계를 오갈 때 만들고 버리기를 반복한다 (히스테리시스) |
| 프레임 예산 | 2청크 (저사양 1) | 한 프레임에 여럿 만들면 화면이 뚝 끊긴다 |
| 갱신 시점 | 청크 경계를 넘을 때만 | 매 프레임 반경 전체를 훑을 필요가 없다 |

청크가 나고 질 때 `onLoad` / `onUnload` 로 바깥에 알린다.
지금은 `Encounters` 가 이걸 받아 야생 적을 세우고 거둔다.

## 5. 충돌

무한 지형이 들어오면서 `Collision` 에 격자 분할(16m)을 얹었다.
예전에는 상자가 수백 개뿐이라 매 틱 전부 훑어도 됐지만, 청크가 계속 붙으면
수천 개가 되고 그걸 120Hz로 훑으면 이동만으로 프레임이 죽는다.

```js
collision.addBox(x, z, w, d, minY, maxY, rotY, owner)   // owner = chunk.key
collision.removeOwner(chunk.key)                        // 청크를 버릴 때
```

**청크가 상자를 넣을 때는 반드시 `owner` 를 단다.** 안 걷어내면
가보지도 않을 땅의 담장에 계속 부딪힌다.

## 6. 바이옴

`Biome.js` 의 표가 전부다. 고도·습도 두 축으로 고른다 — 실제 지리학에서
기후를 나누는 방식과 같아서 결과가 자연스럽다.

```js
elev  = fbm(seed+101, x/460, z/460)     // 높은 곳 → 아르곤 고원 · 수정 지대
moist = fbm(seed+977, ...)              // 습한 곳 → 숲 · 석회암
far   = 원점에서의 거리 / 1100           // 멀수록 험한 땅
```

`far` 편향이 있는 이유는, 이게 없으면 시작하자마자 방사성 황무지에 떨어져
죽기 때문이다.

각 바이옴은 다음을 정한다.

| 필드 | 쓰임 |
|---|---|
| `ground` / `groundAlt` / `tex` | 지형 색과 텍스처 |
| `height` / `rough` | 높낮이 배율과 능선 노이즈 비중 |
| `props` | 무엇이 청크당 몇 개 |
| `danger` | 적 레벨 보정 |
| `ambience` | 안개·조명 (`ZoneManager` 가 보간한다) |
| `teaches` | 처음 밟을 때 한 번 뜨는 화학 설명 |

**`ambience.far` 는 시야 반경(192m)보다 작아야 한다.** 크면 지형이 끊긴
가장자리가 눈에 들어온다.

## 7. 지형에 손댈 때 확인할 것

```
node tools/check-terrain.mjs
```

다섯 가지를 본다.

1. **결정성** — 같은 좌표가 언제나 같은 결과인가.
   깨지면 청크를 버렸다 다시 만들 때 땅이 바뀐다
2. **이음매** — 청크 경계에서 높이가 어긋나지 않는가. 어긋나면 벽처럼 솟는다
3. **바이옴 분포** — 10종이 다 나오는가, 시작 지점이 안전한가
4. **경사** — 걸어서 못 넘는 절벽이 얼마나 되는가 (12%를 넘으면 실패)
5. **대륙의 끝** — 아주 멀리 나가면 바다가 나오는가

그리고 실제로 돌려 본다.

```
node tools/probe-walk.mjs http://localhost:3100 12
```

## 8. 이 시스템이 깨뜨렸던 것들

무한 지형을 넣자 "평지이고 세계가 178m 안에 있다"는 전제 위에 있던 코드가
한꺼번에 터졌다. 비슷한 것을 또 만들 때 참고할 목록이다.

| 증상 | 원인 |
|---|---|
| 땅이 얼룩덜룩 깜빡임 | 마을 풀밭 판과 청크 지형이 마을 안에서 정확히 같은 높이에 겹쳤다 |
| 몬스터가 공중에 뜸 | `Enemy` 가 매 프레임 메시 y를 `0` 으로 못 박고 있었다 |
| 마을 나무 밑동이 잘림 | 손으로 지은 세계는 220m까지인데 평지 고정은 62m였다 |
| 뒤에 거대한 검은 반구 | 하늘돔이 원점 반경 400m 고정이라 걸어서 하늘 밖으로 나갔다 |
| 투사체가 땅속에서 발사 | 절대 `y=1.15` 고정 |
| 적이 쓰러지며 허공으로 꺼짐 | 사망 연출이 `y=0` 기준이었다 |

공통점은 하나다 — **하드코딩된 절대 좌표.**
새 값을 쓸 때 "이 값이 언제 틀려지는가"를 먼저 묻는다.
